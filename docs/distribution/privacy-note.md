# 隱私說明

適用版本：Remote Keyboard v0.2.0 測試版。

## 你打的文字去了哪裡

| 情況 | 文字的去向 |
|---|---|
| 遠端模式 | 從 iPhone 經藍牙加密傳到你配對的電腦（Mac、Windows 或 Linux），再輸入到電腦目前的欄位 |
| 本機模式 | 直接輸入到 iPhone 目前的欄位，不傳到電腦 |

文字不會傳到開發者或任何伺服器。App 與接收端的紀錄只有事件種類、長度、時間與結果，不含文字內容。

## 觸控板與 Wi-Fi

iPhone 與電腦在同一個 Wi-Fi 網路時，觸控板的游標資料（移動、點按、捲動）會經區域網路加密傳到電腦，不經過網際網路，也不傳到任何伺服器。打字內容與配對一律走藍牙，不會經 Wi-Fi 傳送。可以在 App 的「設定 > 觸控板」關閉「經 Wi-Fi 傳送游標」，之後游標資料也只走藍牙。

## 需要開啟的權限

| 位置 | 權限 | 用途 |
|---|---|---|
| iPhone | 鍵盤的「允許完整取用」 | 藍牙連線、手寫辨識、自訂按鍵音量與震動 |
| iPhone | 藍牙 | 連線到電腦 |
| iPhone | 區域網路 | 經 Wi-Fi 傳送游標資料；不允許時游標改走藍牙 |
| Mac | 藍牙 | 接收 iPhone 傳來的資料 |
| Mac | 輔助使用 | 把文字輸入到目前的欄位、判斷目前是否為密碼欄、控制游標 |
| Mac | 區域網路 | 經 Wi-Fi 接收游標資料 |
| Linux | 遠端桌面 | 把文字與游標動作送到桌面，第一次執行時由系統詢問 |

配對金鑰不會傳給開發者。iPhone 上的金鑰存放在鑰匙圈，不會隨備份搬到另一部 iPhone。Mac 上的金鑰存放在 `~/Library/Application Support/RemoteKeyboardReceiver/pair-key`，只有你的 macOS 使用者帳號能讀取；以同一個帳號執行的其他程式也讀得到這個檔案，所以不要在 Mac 上執行來源不明的程式。Windows 上的金鑰存放在目前使用者的「認證管理員」，Linux 上的金鑰存放在 GNOME 鑰匙圈，同樣只要以你的帳號執行的程式都可能讀到。

## 聽寫

聽寫由 iOS 處理，適用 Apple 的聽寫隱私規定。遠端模式下，聽寫結果會經藍牙同步到 Mac；可以在 App 的「聽寫」關閉「聽寫同步到 Mac」。

## 手寫辨識與 Google

手寫使用 Google ML Kit。筆跡與辨識結果都在 iPhone 上處理，依 Google 的說明不會傳到 Google 伺服器。

使用手寫時，ML Kit 會連到 Google：

- 下載手寫模型與取得更新。
- 傳送使用與效能資料，用於診斷和分析。內容包括裝置型號與系統版本、App 識別碼與版本、每次安裝的識別碼、效能數據、事件種類、錯誤代碼，以及設定的語言。

詳情請見 [ML Kit 條款](https://developers.google.com/ml-kit/terms)與 [ML Kit 資料揭露](https://developers.google.com/ml-kit/ios-data-disclosure)。

不想連到 Google，可以不下載手寫模型，改用速成或英文輸入。

## 密碼欄與鎖定畫面

Windows 與 Linux 接收端沒有這項保護：文字會送到目前最前面的視窗，包括密碼欄。

Mac 目前的欄位是密碼欄、系統開啟安全鍵盤輸入，或螢幕已鎖定時，Receiver 不會輸入文字。

這項保護只涵蓋系統標示為密碼欄的欄位。以下情況偵測不到，文字仍會送出，請不要用這個鍵盤輸入密碼：

- 其他終端機 App 內的 `sudo`、`ssh` 等密碼提示。macOS 27.2 的 Apple 終端機在隱藏輸入時有擋下文字，其他終端機與系統版本未驗證。
- 遠端桌面或虛擬機視窗內的密碼欄。
- 自行繪製、未標示為密碼欄的輸入框。

## 回報問題時

請不要傳送密碼、Apple 帳號資料、雙重驗證碼、配對檔或憑證。
