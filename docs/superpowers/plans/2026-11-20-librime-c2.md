# librime C2 內建輸入法 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 librime 上內建倉頡（第五代）、注音、粵拼、漢語拼音四個方案，速成同時擴充收香港增補字，鍵盤中文頁改由鍵位 JSON 畫鍵。

**Architecture:** 詞典由新的 SwiftPM 工具 `scripts/rime/ImeDataTools` 從鎖定版本的上游資料產生，產物與 C1 一樣提交在 `ime/rime/`；方案設定由我們自寫。`RimeInputMethod` 以 `RimeSchemeConfig` 支援五個方案（表格型與整句型）。鍵位以 `ime/layouts/*.json` 描述，Core 負責解析、驗證與計算位置，鍵盤以 `LayoutPageView` 畫出。Xcode build phase 仍只執行 `rime_deployer`。

**Tech Stack:** C1 的全部（librime 1.17.0 等）；資料：libcangjie `table.txt`（C1 已鎖定）、小麥注音 3.1.1 的 `Source/Data`（MIT）、Unihan 18.0.0（Unicode License v3）、words.hk 數據 2026-11-20 快照（公有領域）。

**Spec:** `docs/superpowers/specs/2026-11-20-librime-input-engine-design.md`（D31，§7.2 為本計畫範圍；§5 的 U3、U7、M2、M4、M7、M8、M10、M11、M15）

## 主代理決定（使用者可在批准時更改）

| 編號 | 決定 | 理由 |
|---|---|---|
| P1 | 產生的 `.dict.yaml` 提交進 repo（沿用 C1 的 `quick5.dict.yaml` 做法），build phase 不執行 Swift | Xcode build phase 的 `SDKROOT` 指向 iOS，在其中跑 Swift 工具容易失敗；建置也不必下載詞典來源 |
| P2 | words.hk 數據沒有固定版本的網址，把 2026-11-20 的快照（約 2 MB，公有領域）提交到 `ime/sources/wordshk/` | 鎖定檔的 checksum 會在 words.hk 更新時失效；快照才能重現 |
| P3 | 小麥注音只用原始資料檔，權重照其 `main_compiler.py` 與 `frequency_builder.py` 的規則換算成整數，不執行其 Python | 不增加 Python 依賴；規則寫在 Task 2，可測試 |
| P4 | 注音採大千鍵位；一聲不打聲調鍵，其他聲調鍵可省略；空白鍵一律選第一個候選字 | 與速成的空白鍵行為一致 |
| P5 | 拼音與粵拼的碼不含聲調 | QWERTY 頁沒有數字鍵 |
| P6 | 鍵位檔三個：`cangjie-qwerty`（速成、倉頡）、`latin-qwerty`（拼音、粵拼）、`zhuyin-standard`。前兩個幾何相同，只有鍵面不同，即 spec 所說「QWERTY 加字根或字母標示」 | 字根與字母的鍵面不能共用 |
| P7 | 注音頁有四行字鍵，鍵盤比 QWERTY 頁高 54 pt（一行鍵高 42 加行距 12） | 縮小鍵高會降低命中率 |
| P8 | 速成以外的方案在 librime 失敗時不退回 Swift 速成，中文頁顯示 M8 的文字，按鍵照英文鍵輸出；速成照 C1 退回 Swift 速成 | Swift 速成即將刪除（U4）；換版面退回反而更混亂 |
| P9 | 有輸入碼時按 Return：清除輸入碼（沿用 C1）。spec §10 要求與使用者確認一次 | 待使用者在批准本計畫時確認 |
| P10 | M7 的鍵盤內切換要等 C1 實機 D4（沒有完整取用時能否讀 App Group）的結果，本計畫不做 | spec M7 以 C1 量測為條件 |
| P11 | 中文頁按鍵的 accessibility identifier 由 `rk.quick.*` 改為 `rk.ime.*` | 五個方案共用一個頁面 |
| P12 | 版面每行置中，QWERTY 第三行的 Shift 與刪除鍵左右各內縮半個鍵距（3 pt），與現有速成頁差 3 pt | 一條規則適用所有版面，C4 匯入的版面也照此排 |
| P13 | 小麥注音 `BPMFBase.txt` 有 4 行大千鍵欄與注音不符（上游錯誤）：注音碼一律由注音欄換算，第 4 欄只用來核對並列出 | 照第 4 欄會產生錯碼（如「公」） |

## Global Constraints

- 部署目標 iOS 18.0、macOS 15.0；Swift language mode 6；`ImeDataTools` 只需 macOS 15。
- 原始碼與資料版本固定於 `scripts/rime/versions.lock`，下載後核對 SHA-256（M13）。
- 方案設定一律 `enable_user_dict: false`（M4）；鍵盤執行時不編譯詞典（M2）；不編入 Lua 與外掛（M3）。
- 內建資料只用：libcangjie（Public Domain）、小麥注音 `Source/Data`（MIT）、words.hk 字詞表與頻率表（公有領域，註明出處）、Unihan（Unicode License v3）。不得使用 rime-cantonese、RIME 官方方案、libchewing、CC-CEDICT、教育部辭典的任何內容（spec §8）。方案設定檔由我們自寫，不得複製 RIME 官方方案的檔案。
- 倉頡與速成收字與排序（U7）：Big5 與 HKSCS 的漢字；同碼時 Big5 字在前，依 libcangjie 排序值由高到低、同值保留檔案次序；HKSCS 字在後，依 words.hk 字頻由高到低、同頻保留檔案次序。
- 方案 ID：`quick5`、`cangjie5`、`zhuyin`、`pinyin`、`jyutping`；`ChineseInputMethodID` 原始值：`handwriting`、`quick`、`cangjie`、`zhuyin`、`jyutping`、`pinyin`（spec §6.3）。
- 本計畫不刪除 Swift 速成（U4、U6）。
- log 只記事件種類、數量、時間與結果，不記打過的文字、輸入碼或候選字。
- 子代理不得 commit 或 push；每個 Task 結束時由主代理重跑驗證後 commit。
- 改 `project.yml` 後執行 `xcodegen generate`，再 `LANG=en_US.UTF-8 pod install`；build 一律用 `-workspace RemoteKeyboard.xcworkspace`。
- 產品文字用台灣繁體中文用字。

## Review Focus

1. 鍵盤擴充程式的行程沒有結束，使用者在主 App 換了方案再叫出鍵盤：必須用新方案，不得沿用舊方案的 session。測試在 Task 7（`testSwitchingSchemeTakesEffectOnReopen`）。
2. 整句型方案只選了前半句的候選字：其餘輸入碼保留給下一次選字，不得提早送出或丟失。測試在 Task 5（`testPartialSelectionKeepsTheRestComposing`）。
3. 拼音型方案一直打字不選字：輸入碼上限 60 鍵，候選字最多讀 200 個，鍵盤不得卡住。測試在 Task 5（`testInputStopsAtMaxCodeLength`、`testStateReadsAtMostCandidateLimit`）。

**Interfaces:**
- Produces（`ImeData` library，Task 2、3 沿用）：
  - `public enum CSV { public static func rows(_ text: String) -> [[String]] }`：逗號分隔；`\r\n` 與 `\n` 都是列尾（words.hk 的檔案是 CRLF）；雙引號包住的欄位可含逗號、`\r` 與換行，`""` 代表一個引號。以 Unicode scalar 逐一處理（`"\r\n"` 在 Swift 是一個 Character）。
  - `public enum Han { public static func isAllHan(_ text: String) -> Bool }`：範圍與 Core 的 `HanCharacters` 相同（複製，不依賴 Core）。
  - `public enum ImeDataError: Error, Equatable { case badLine(Int) }`
  - `public struct DictEntry: Equatable, Sendable { public var text: String; public var code: String; public var weight: Int? }`
  - `public enum DictWriter { public static let version = "2026.11.20"; public static func render(name: String, sort: String, sources: [String], entries: [DictEntry]) -> String }`
  - `public struct CangjieRow: Equatable, Sendable { public var character: String; public var isBig5: Bool; public var codes: [String]; public var order: Int }`
  - `public enum CangjieTable { public static func parse(_ text: String) throws -> [CangjieRow] }`：略過 `#` 行與空行（行號仍以檔案行計）；欄數不是 15 時丟 `ImeDataError.badLine(Int)`（行號從 1 起算）；只收第 3 欄為 1 且（第 4 欄或第 5 欄為 1）的行；`codes` 取第 13 欄（第五代），為 `NA` 時取第 12 欄，以逗號分開；保留檔案次序。
  - `public enum WordsHKFrequency { public static func parse(_ csv: String) -> [String: Int] }`：略過第一列（`Source,…`）。
  - `public enum CangjieDicts { public static func cangjie5(_ rows: [CangjieRow], frequency: [String: Int]) -> [DictEntry]; public static func quick5(_ rows: [CangjieRow], frequency: [String: Int]) -> [DictEntry] }`
  - 命令列：`make-ime-dicts --src <build/rime/src> --wordshk <ime/sources/wordshk> --out <資料夾>`，寫出該資料夾內的 `*.dict.yaml`。

final class CSVTests: XCTestCase {
    func testQuotedNewlineAndComma() {
        XCTAssertEqual(CSV.rows("Source,x\n\"\n\",5\n\",\",3\n\"a\"\"b\",1\n"),
                       [["Source", "x"], ["\n", "5"], [",", "3"], ["a\"b", "1"]])

        XCTAssertEqual(CSV.rows("a,b\r\n\"\r\",7\r\nc,d\r\n"), [["a", "b"], ["\r", "7"], ["c", "d"]])

    曰 曰 1 1 0 0 0 0 0 0 0 a a NA 8000
    嘅 嘅 1 0 1 0 1 0 0 0 0 rhpu rhpu NA 0

    啱 啱 1 0 1 0 0 0 0 0 0 rmbu rmbu NA 0

**規則（對應小麥注音的 `frequency_builder.py` 與 `main_compiler.py`，換算到次數）：**

1. 單字：`BPMFBase.txt` 每行為「字 注音 拼音 大千鍵 類別」；只收字為漢字的行。注音碼為 `BopomofoKeys.keys(for: 第 2 欄)`（P13）；與第 4 欄不同時計入 `keyMismatches` 並由命令列列出該行，不中止。拼音碼取第 3 欄去掉結尾的聲調數字。
2. 詞：`BPMFMappings.txt` 每行為「詞 音節 音節 …」；只收全為漢字、且在 `phrase.occ` 中出現的詞。注音碼為各音節的 `keys(for:)` 以空白連接；拼音碼為各音節查「`BPMFBase.txt` 中同一注音音節的拼音（去聲調）」以空白連接。任何音節查不到時丟棄該筆並計入 `dropped`。
3. 修正次數 a(k)：`phrase.occ` 的次數，減去 `exclusion.txt`（略過 `#` 行與少於兩欄的行，以空白或 tab 分欄）中每一列（k, v）且 v 包含 k、k 與 v 都在 `phrase.occ` 時 v 的原始次數；結果小於 1 或 k 不在 `phrase.occ` 時 a(k) = 0.5。
4. 分數 s(k) = a(k) × 2.7^(字數 − 1)。
5. 多音字（只對單字）：字不在 heterophony1，或讀音等於 heterophony1 所列 → 權重 max(1, round(s))；否則字不在 heterophony2 → 6；讀音等於 heterophony2 → max(6, round(s / 4.93))；否則字不在 heterophony3 → 6；讀音等於 heterophony3 → max(6, round(s / 24.3))；其餘 → 6。倍率與預設值由小麥注音在 log10 值上減 0.693（ln 2）與 `H_DEFLT_FREQ = -6.8` 換算到次數（norm 約 4.0×10⁷）。
6. 其餘情況權重 = max(1, round(s))，四捨五入為遠離零（Swift `rounded()`）。同一個（字詞、碼）只留權重最大的一筆。依碼由小到大、權重由大到小、字詞由小到大排序。
7. 兩份詞典 `sort: by_weight`，有權重欄；`sources` 寫明小麥注音 3.1.1 的 commit 網址與 MIT。

**位置演算法：** 每行寬度單位 W(row) = 該行各鍵 `width` 之和；取 W 最大的一行為基準（同值時取鍵數多的一行），單位寬 u = (總寬 − (基準行鍵數 − 1) × gap) / 基準行 W。每鍵寬 = width × u，鍵與鍵之間隔 gap，整行置中。`height(rows:)` = rows × `KeyboardMetrics.keyRowHeight` + (rows − 1) × `KeyboardMetrics.rowGap`。
