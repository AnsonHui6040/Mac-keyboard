# 2026-11-02 輸入與觸控板更新驗收

工作目錄：`Mac-keyboard-sidestore`，分支 `sidestore-distribution`，未提交。

## 決定

| 項目 | 決定 |
|---|---|
| 即時模式、Mac 不能輸入 | 不進草稿，文字不保留。密碼欄、安全輸入、鎖定畫面顯示「密碼不能輸入」；沒有輸入欄位提示「Mac 沒有輸入欄位，未輸入」 |
| 草稿模式、Mac 不能輸入 | 密碼狀態下文字與換行丟棄，退格與游標可用；沒有輸入欄位時照常進草稿 |
| 草稿編輯 | 點按移動游標，拖曳連續移動 |
| 雙擊 | 兩次輕點相隔 500 ms 內、距離 12 pt 內，第二次送 count 2。iPhone 用固定值，因為 macOS 以事件的 click state 判斷，不需要傳 Mac 的設定 |
| 右鍵 | 雙指輕點，各自位移 12 pt 內，按下到全部放開 300 ms 內 |
| 輕點後按住拖曳 | 輕點後 500 ms 內、12 pt 內再按下，按住超過 200 ms 或移動超過 8 pt 即按下左鍵拖曳，不送雙擊。按住 0.4 秒拖曳保留 |
| 傳輸次數 | 只在 App 設定調整，下次開啟鍵盤生效 |
| Mac 測試插入與除錯 | `ReceiverPanel.showsDeveloperTools = false` 隱藏，程式保留。跑 T04、T15 前要改回 `true` |

數值 500 ms、12 pt、300 ms 都是暫定值，等真手指使用後調整。

## 審查保留項目

| 項目 | 處理 |
|---|---|
| 草稿模式剛切到密碼欄的約 250 ms，或尚未收到第一個狀態時，字可能先進草稿 | 保留。傳送會被 Mac 拒絕，文字不會輸入密碼欄 |
| 其他 App 開著安全輸入時，一般欄位也顯示「密碼不能輸入」 | 保留，安全方向失敗，已寫入指南與發佈說明 |
| 傳送草稿的同時 Mac 變成不能輸入，草稿會遺失 | 保留，文字沒有送進 Mac，原本已有相同情況 |
| 通道未開時的第一次輕點仍計入雙擊 | 保留，時間窗很短 |
| 輸入法忙碌時拖曳草稿，游標可能短暫不準 | 保留，只影響顯示 |
